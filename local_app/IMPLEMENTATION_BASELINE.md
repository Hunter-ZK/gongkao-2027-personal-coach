# Workbench V2 冻结实施基线

> 冻结日期：2026-09-14  
> 取代：Workbench V1 中与前端形态、PDF人工确认、跨设备同步相冲突的旧约束。

实现与测试出现冲突时，以本文件、当前数据库契约和产品测试为准，不再回退到旧静态前端或“长文为主”的隐含假设。

## 一、考试与事实边界

- 国考按副省级规划；135题仅为历史/规划基线，2027 官方公告发布后校准。
- 国考 70/70、广东行测90/申论80均为目标展示，不作为无数据支撑的阶段硬门槛。
- 预测考试日期必须标明非官方；官方发布后替换。
- 模块/题目分值用于规划时必须标识为估算，不冒充官方逐题评分。
- 广东多选题精确计分规则无可靠依据时保持 unknown。
- 无法合法复现的真题不伪称真题；使用改编题时明确标注。

## 二、唯一产品与视觉基线

- `local_app/` 是唯一当前产品主线；旧 `docs/v3` 静态前端不再作为入口、数据源或设计依据。
- `Civil_gemini2` 是正式视觉/交互母版：允许复用其卡片密度、侧栏、顶栏、标签、Chip、表格、弹窗、间距和交互结构。
- 只复用视觉与交互，不引入 `Civil_gemini2` 的 mock 数据；所有业务页面必须读取本工作台真实 API / SQLite 数据。
- 训练记录/题库、错题本、错题复训沿用已经落地的 Gemini 精确视图。
- 新页面优先采用卡片、分组、标签、可展开区域与渐进披露，不把完整信息一次性铺成长篇页面。

## 三、行测知识体系

行测知识体系是当前最高优先级学习功能。

每个知识节点采用三层阅读：

1. **快速恢复（30秒）**：看到什么 / 第一动作 / 边界止损 / 我的真实证据；
2. **标准学习（5–15分钟）**：定义、底层原理、识别信号词库、标准步骤、考场指令、例题、陷阱、相邻方法选择；
3. **深度理解（按需）**：完整扩展讲义、正式来源、历史笔记、个人训练证据。

固定要求：

- 识别信号使用可点击 Chip / 词库式展示；
- 正式方法按 `method_to_node` 静态映射，不用页面关键词猜测归属；
- 长篇讲义与历史笔记完整保留，但默认折叠；
- 每个节点展示真实训练正确率、可靠速度样本、关联错题和掌握状态；
- AI 教练入口携带当前节点上下文。

## 四、PDF → 题库 → 错题 → AI 闭环

- 粉笔“快速智能练习”使用固定版式几何解析器，不以 OCR 作为默认路径。
- 可信固定模板满足题号、题干、ABCD、用户答案、正确答案和结构校验后，可自动 `verified=1`。
- **可信固定模板不再要求逐题人工确认**；解析完成后直接自动入库。
- 只有答案缺失、选项不完整、题号异常、图片/资料归属不确定、版式变化等异常题进入人工校对。
- 入库必须同时形成：`training`、`question_bank`、`question_attempt`；同题重复出现累计 Attempt，不复制为多道题。
- 做错题自动写入 `mistake`，进入复训队列。
- PDF commit 后由后端自动调度错题 AI，不依赖前端再次点击。
- AI 分析优先使用本地 `gongkao-method-coach` Skill 与 V2 方法库，输出标准解、可靠快解及适用条件、命题陷阱、建议错因和关联知识节点。
- `mistake.cause_primary` 在待诊断状态允许为空；AI建议错因不未经确认冒充确定事实。

## 五、双设备数据同步

- SQLite 仍是单设备运行时数据库。
- 公司/家里接续采用 **Git Checkpoint 伪实时同步**，不建设实时云数据库。
- 公开 `gongkao-2027-personal-coach` 仓库不得保存个人 SQLite、题目图片、API Key 或密钥配置。
- 默认私有数据交换区：`Hunter-ZK/Civil_gemini2` 的 `gongkao-personal-data` 分支。
- 工作台在本机 `data/sync-repo/` 维护私有同步缓存；首次提交/拉取时自动初始化。
- “提交本机进度”同步 SQLite 快照及 `data/images/`；“拉取云端进度”恢复快照和图片。
- 拉取前必须自动备份本机数据库。
- 本机与云端同时存在新版本时禁止静默覆盖；必须先解决顺序或明确强制拉取。
- `data/secrets.json`、DeepSeek API Key、本机同步状态、备份、上传临时文件均不得进入同步快照。
- 新设备首次访问私有同步仓库时，需要本机 Git 已完成可访问该私有仓库的 GitHub 身份认证。

## 六、数据、训练与能力判定

- 历史数据只在可靠映射时迁移，不补造未知字段。
- 原始旧笔记与二手整理必须区分来源等级，不用二手稿冒充原始笔记。
- 正式内容节点保持 30 个行测 + 5 个申论；建设进度不得伪装成“已完成”。
- 整组用时均摊只作估算；节点速度门槛只采用可靠计时样本。
- 正确但超时、长期二选一、卡题不止损同样属于训练信号，不以正确率单指标判定掌握。
- 错题原题层与错误模式层分离；结构性错误进入后续复训和计划调度。

## 七、运行与验收

- Windows/macOS/Linux 正常使用仍通过 `local_app` 启动脚本进入，不要求用户单独启动 Node 开发服务器。
- PDF 导出继续采用打印友好 HTML + 浏览器“打印/另存为 PDF”。
- 未获得真实新导出样本的其他 PDF 类型不得猜正则扩展解析器。
- 合并到 `main` 前必须通过 GitHub Actions 的 Ubuntu / Windows / macOS 三平台 CI：Python 测试、compileall、前端语法检查、前端启动 smoke、视觉 lint、内容 lint。
- 双设备同步至少需要真实临时 Git remote 集成测试，验证快照 commit/push、远端可读取和本机 dirty 状态检测。
- AI 网络调用因 CI 不持有个人 API Key 时不伪称已进行线上调用；必须验证自动调度、Skill 检索链路和无 Key 时的可恢复行为。
