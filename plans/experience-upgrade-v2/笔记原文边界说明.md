# 笔记原文边界说明

> 目的：在 B1/B7 改造前，明确“什么是不可改原文，什么是派生信息，什么是新增扩写”。

## 1. 四层内容身份

### 1.1 正式原文层（Immutable Original）

当前应用真正用于知识页正文的正式原文，来源为：

- `local_app/content/nodes/*.md`

判定：
- YAML front matter 不是学习正文，不参与正文字符 diff；
- front matter 后的 Markdown 正文属于正式原文；
- 正文在 B1 中只允许剪切、移动、重新归位；
- 禁止改字、改标点、改数字、改公式、概括、润色、同义改写。

### 1.2 来源/历史材料层（Source / Legacy）

包括：

- `notes/xingce/*.md`
- `local_app/content/legacy_notes/*`
- `local_app/content/methods/source/*.json`
- 已审阅 GitHub Skill 摘要与 evidence 文件

用途：
- 追溯正式原文来源；
- 为“出处层”提供完整上下文；
- 为扩写执行“先找，再生成”。

这些内容不是默认阅读首页，也不应被 AI 直接冒充老师逐字原话。

### 1.3 派生阅读层（Derived Reading Layer）

包括：
- 唤醒层信号表；
- 情形级虚拟 ID；
- 推荐理由；
- 数据带；
- 目录、锚点、分类标签；
- 自动计算的验证统计；
- 多师方法的采用/弃用状态。

性质：
- 可以由程序计算或结构化整理；
- 不写回正式原文；
- 不参与原文字符级 diff。

### 1.4 扩写层（Expansion Layer）

固定类型：
- 为什么
- 边界
- 易混
- 陷阱
- 演示
- 我的批注

性质：
- 独立 JSON 记录；
- 必须锚定一个具体原文句子；
- 记录原文锚点 hash；
- 原文变化后自动标记“待复核”；
- 唤醒层永远不显示扩写；
- AI 扩写不得写回原文文件。

## 2. 快照范围

批量切分前建立：

`notes/_snapshot_before_split/formal_nodes/`

完整复制所有 `local_app/content/nodes/*.md`。

同时建立：

`notes/_snapshot_before_split/source_notes/`

复制本轮用于追溯的 `notes/xingce/*.md`。

正式零差异验收以 `formal_nodes` 为准。

## 3. 情形级身份

不新增数据库表、不新增 `knowledge_node` 行。

情形级 ID：

`{parent_slug}::{unit_id}`

例如：

`data-two-period-proportion::direction-only`

原则：
- `parent_slug` 永远指向现有正式节点；
- `unit_id` 为稳定英文 kebab-case；
- 一旦进入用户数据（阅读历史/扩写/采用状态），不得随意改名；
- 若后续必须更名，通过 alias 映射兼容旧 key，不做数据库迁移。

## 4. 不允许的做法

- 把 AI 解释直接插进 `content/nodes/*.md` 原文；
- 为了让段落顺畅而补连接词；
- 把同一句原文复制到两个情形正文；
- 把多个老师说法融合后标成“名师原文”；
- 把“同型改编题”当成 B7 的“演示真题”；
- 用 AI 自编例题补空缺。

## 5. 允许的做法

- 将原文段落剪切到新的情形文件/结构记录；
- 用引用指针让多个派生视图指向同一原文片段；
- 从历史讲义找回解释并标记 `名师原文补充`；
- 单独新增 `AI 生成 · 未验证` 扩写；
- 记录用户自己的批注与采用状态；
- 对原文中疑似错误新增“边界/存疑”扩写，但不改原文。
