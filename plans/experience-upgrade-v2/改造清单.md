# gongkao-2027-personal-coach 体验升级 v2 · 改造清单

> PR0 文档基线。仅冻结改造范围，不提交业务代码。
> 
> 硬约束：不改数据库 schema；不新增导航模块；不重写 React/FastAPI 技术栈；不改写、概括、删减正式笔记原文。

## 1. 用户可见变化总览

| 区域 | 当前 | 改造后 |
|---|---|---|
| 知识库入口 | 先看目录树，自行挑笔记 | 首屏直接给 5–8 条已排序推荐笔记，目录树降为“浏览全部笔记” |
| 训练入口 | 先看训练记录/题库，自行挑题 | 首屏给 3–5 组系统配好的题组，底部保留“自选题目” |
| 知识正文 | 一课一篇、目录+大正文卡片 | 情形级笔记；唤醒/方法/出处三种阅读形态；单栏阅读页 |
| 多师方法 | 综合成一套说法 | 同情形并列署名，保留分歧；用户可指定“我采用”与“已弃用” |
| 笔记解释 | 蒸馏结论较密 | 原文逐字保留；在句子旁新增独立扩写层 |
| 笔记验证 | 静态阅读 | “按这个方法练 5 题”，训练结果回到笔记形成验证证据 |
| 题库/错题 | 大卡片，首屏扫描量低 | 密行列表，首屏 ≥8 条 |
| 做题页 | 标签、卡片、进度、解析混在一起 | 作答时只保留题干+选项、剩余时间、暂停并退出 |
| AI 诊断 | 长文本 | 固定 JSON 结构，先给结论/动作，再异步补深度诊断 |
| AI 反馈 | 只读 | 认同 / 错因不对 / 一次性失误；用户判断覆盖 AI |
| PDF/校对/同步 | 显式操作占主流程 | 后台化；只通过徽标与冲突提示打扰用户 |
| 禅模式 | 隐藏部分词汇、暗色化 | 全局工作文档外观：无彩色、无徽标/进度条、中性标题、衬线正文 |

## 2. A：入口之后的内容决策

### A1 知识推荐首页

- 新增知识推荐接口与排序服务，不新增导航。
- 排序信号：
  1. 24h 内做错且关联节点；
  2. 关联错误模式复发次数；
  3. 距上次查看天数 × 历史错误次数；
  4. 明日/本周计划覆盖节点。
- 历史阅读记录当前不存在：升级后开始真实记录，历史权重不得伪造；无记录时该项记 0。
- 目录树保留，通过“浏览全部笔记”进入。

主要文件：
- `local_app/frontend/src/components/views/KnowledgeView.tsx`
- `local_app/routers/knowledge.py`
- `local_app/services/knowledge_reader.py`
- `local_app/routers/plan.py`
- `local_app/routers/mistakes.py`

风险：中。

### A2 刷题推荐首页

- 训练模块首屏展示 3–5 个推荐题组。
- 复用 `question_bank`、`question_attempt`、错题复训调度，不建立第二套题库。
- 当前题库点击后仅是只读详情，必须把题库题目接入统一作答流程。
- 推荐题组包括：错题到期组、同类新题组、薄弱题型限时组、速度超时组等。

主要文件：
- `TrainingsView.tsx`
- `ReviewView.tsx`（抽取可复用作答交互）
- `local_app/routers/training.py`
- `local_app/services/question_bank.py`
- `local_app/services/scheduler.py`

风险：高。

### A3 中断恢复

- 统一活动题组会话状态。
- 保存内容：题组 id、当前题序、已选答案、总剩余秒数、当前题已用时、更新时间。
- 保存时机：每题作答后 + 每 15 秒。
- 浏览器关闭/断电后恢复误差不超过 1 道。
- 恢复条出现在训练/复训/知识推荐页顶部。
- 状态存现有 `setting.value_json`，key：`active_practice_session_v2`。

主要文件：
- `AppContext.tsx`
- 通用作答视图
- `training.py`
- `misc.py` 或新增 router 内的 setting 读写接口（不新增表）

风险：高。

### A4 苦役后台化

- PDF 上传请求只负责接收并创建任务状态；解析/校对准备在后台执行。
- 人工校对通过徽标进入，不弹窗阻塞。
- 同步：启动自动 pull；有效学习会话结束自动 push；仅冲突提示。
- 手动同步保留在设置区。

主要文件：
- `ImportView.tsx`
- `training.py`
- `sync.py`
- `services/device_sync.py`
- Header/Sidebar/AI 设置区

风险：中高。

## 3. B：笔记展示与使用

### B1 情形级切分

- 正式原文来源以 `local_app/content/nodes/*.md` 为主验收对象。
- 切分只允许剪切、归位、重组；禁止改写、概括、删减。
- 情形级虚拟 ID：`{parent_slug}::{unit_id}`。
- 不新增 `knowledge_node` 行，不迁移历史 `question.node_slug`。
- 切分前完整快照到 `notes/_snapshot_before_split/`。
- 切分后必须字符级校验：原文层按原顺序拼接后，非空白字符差异数必须为 0。

风险：最高。

### B2 唤醒 / 方法 / 出处三层

- 唤醒：题干级信号 → 考场动作；无解释、无例题。
- 方法：完整方法步骤 + 判断点 + 止损 + 紧邻例题片段；默认展开。
- 出处：完整讲义、推导、命题背景、历史笔记；默认收起。
- 当前 `knowledge_reader.py` 的自动章节重排不再被视为“正式原文层”。

### B3 多师分歧与采用状态

- 同一情形下不同老师/Skill 证据并列，不再强行融合。
- 用户采用状态存 `setting.value_json`：`method_adoption_v1`。
- 支持 `采用 / 已弃用 / 候选`。
- 效果依据从现有真实作答记录聚合，不手填虚构数据。

### B4 阅读排版

- 知识正文：单栏、约 60–70 中文字符行宽、17–18px、1.7 行高。
- 方法正文不折叠。
- 长内容不用卡片切碎。
- 只有出处层折叠。

### B5 数据带

顶部显示：
`做过 N 题 · 正确率 XX% · 关联错误复发 N 次 · 最近验证 N 天前`

“最近验证”来自真实作答；“最近查看”单独记录，不混用。

### B6 按方法练 5 题

- 只抽取题库真实题，不生成题。
- 完成后返回原笔记并形成本次验证记录：有效 / 无效 / 待定 + 正确率 + 平均用时。
- 依赖 PR1 的通用题组作答链。

### B7 扩写层

- 与原文物理分离，锚定具体句子哈希。
- 固定类型：为什么 / 边界 / 易混 / 陷阱 / 演示 / 我的批注。
- 每句每类最多 1 条；每句最多 6 条。
- 来源：`名师原文补充` / `AI 生成 · 未验证` / `我自己写的` / `已采纳`。
- 先检索原始讲义/历史笔记，找不到再生成 AI 扩写。
- “演示”只允许使用题库真题。
- 批量生成仅限复发≥2或历史做题数≥10的笔记。
- 删除写入 `被删扩写.log`。
- 状态存 `setting.value_json`：`note_expansions:<note-id>`。

风险：高。

## 4. C：信息密度

### C1 密行列表

适用：题库 / 错题 / 复训候选 / 推荐笔记。

目标：首屏可扫描条目 ≥8。

不机械应用到统计看板、申论长文、方法详情。

### C2 做题页

作答态只保留：
- 题干 + 选项
- 剩余时间
- 暂停并退出

所有统计、熟练度、解析、AI 内容放到提交后或退出后。

### C3 折叠规则

默认展开：诊断结论、考场动作、错因、唤醒层、方法层。

默认折叠：标准解全文、出处层、命题背景、历史原文。

### C4 禅模式

- 整体无彩色；
- 不显示进度条、徽标、醒目标识；
- 标签页标题中性；
- 正文切换衬线体；
- 保持工作文档外观。

## 5. D：AI 诊断

### D1 固定结构

新诊断逻辑结构：
- 一句话结论
- 错因（新 7 类）
- 识别信号（必须来自本题原文）
- 考场动作
- 止损线（具体秒数）
- 关联笔记
- 验证任务
- 置信度

旧 AI 记录继续可读，不做数据迁移。

### D2 Prompt 规则

- 先检索正式笔记和方法，再生成；
- 禁止复述教材定义；
- 识别信号必须是题干原词句；
- 必须给秒数；
- 不确定标未验证；
- 首屏结论+动作总长 ≤60 字。

### D3 可反驳

按钮：认同 / 错因不对 / 一次性失误。

新 7 类错因：
1. 审题漏条件
2. 方法选错
3. 计算失误
4. 知识点缺失
5. 速度不够
6. 二选一不稳
7. 一次性失误

旧 14 类历史错因不改写，通过兼容映射投影到新 7 类。

建议映射：
- 审题错误、主体错误、时间错误、单位错误 → 审题漏条件
- 题型识别错误、方法选择错误、公式调用错误、方法生疏 → 方法选错
- 推理链遗漏 → 二选一不稳（若人工修正则以人工为准）
- 计算错误 → 计算失误
- 速度问题、取舍问题 → 速度不够
- 知识缺口 → 知识点缺失
- 偶发失误 → 一次性失误

### D4 异步化

- 作答提交立即返回：对/错 + 正确答案 + 一句话结论。
- 深度诊断后台运行。
- AI 无 key/失败/超时绝不阻塞下一题。
- 当前 `BackgroundTasks` 基础保留并收口到统一状态展示。

## 6. 零 schema 状态容器

| 状态 | 载体 |
|---|---|
| 未完成题组 | `setting.value_json` / `active_practice_session_v2` |
| 阅读历史 | `setting.value_json` / `note_view_history_v1` |
| 方法采用状态 | `setting.value_json` / `method_adoption_v1` |
| 扩写 | `setting.value_json` / `note_expansions:<note-id>` |
| 诊断人工反馈辅助上下文 | 优先现有 mistake/review 字段，不足再用 `diagnosis_feedback_v1` |
| 实际作答 | 继续使用 `question_attempt` / `review_attempt` |

## 7. 验收红线

以下任一发生即视为失败：

1. 新增数据库 migration；
2. 删除或合并现有导航模块；
3. 正式笔记原文出现非空白字符增删改；
4. AI 自编题进入训练或扩写“演示”；
5. AI 生成内容冒充老师原话；
6. 做题因为 AI 无 key/超时而阻塞；
7. 列表首屏仍低于 8 条；
8. 中断恢复误差超过 1 道题；
9. 禅模式仍出现明显彩色进度/公考徽标。
